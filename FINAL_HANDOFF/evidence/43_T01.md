## 5. Architecture

### 5.1 In-process TenantContext (the "context" layer)

```python
@dataclass
class TenantRecord:
    tenant_id: str
    plan: str
    tier: str
    initial_balance: Decimal
    workflow_runs: List[str]
    idempotency_keys: List[str]

class TenantContext:
    """In-process, self-contained — NO disk / network / Flask / SQL."""
    def register(tenant_id, plan, tier, initial_balance) -> TenantRecord: ...
    def record_run(tenant_id, run_id, workflow_id) -> None: ...
    def runs_for(tenant_id) -> List[str]: ...
    def register_idempotency_key(tenant_id, key) -> bool: ...
```

Design rationale:
- **Why self-contained**: `multi_tenant_manager.py` writes to `C:\Users\xinzh\.openclaw\tenants\` (real disk), `tenant_isolation.py` imports Flask + DB; both conflict with "no side effects" constraint.
- **Why idempotency keys live in context**: the production contract is "context decides whether a wf's bill event is fresh or replay" — having `register_idempotency_key` return `False` on dup lets us test the boundary in Case 2.

### 5.2 Helper `_run_wf_and_bill`

```python
def _run_wf_and_bill(*, ctx, engine, tenant_id, run_id_for_bill, units, idempotency_prefix):
    idem = f"{idempotency_prefix}-{run_id_for_bill}"
    assert ctx.register_idempotency_key(tenant_id, idem)
    ev = _make_event(tenant_id, idem, units)
    res = engine.reserve(ev)
    se = engine.settle(res.entry_id)
    return res, se
```

Five-step chain: `ctx.register_idem → bill.reserve → bill.settle → invariants`.
